## How it was tested

The generator tested is the **shared cryptographic random source** that every game on this engine template draws from, so this result covers the randomness behind all of them.

**Procedure**

- 10,000,000 outcomes were drawn.
- Raw randomness was scaled the same way real games consume it: continuous values binned into equal buckets, and whole-number values drawn directly from a range.
- Every applicable test from GLI-19 §3.2.2 was then run over those outcomes.

**How pass/fail was decided**

- Each test yields a p-value: the probability of seeing a result this extreme *if the generator were fair*. A very small p-value is evidence of unfairness.
- Because several tests run together, the thresholds are corrected for multiple comparisons (**holm-bonferroni**) at **99% family-wise confidence**. Without that correction, running 7 tests would produce false alarms by chance alone.
- The results from the independent batches are combined (Fisher's method) so a consistent small defect is caught while one-off noise is not.
- **Pass** = no test was rejected after correction. Any rejection is reported as a failure.

<details><summary><strong>What each of these tests actually checks</strong></summary>

- **chi-square** — Counts how often each possible outcome came up and compares that to how often it *should* come up. A fair generator spreads outcomes evenly; a biased one over-produces some values.
- **overlaps** — Looks at overlapping runs of consecutive outcomes to check that patterns spanning several draws appear at their expected frequency — catches structure a single-value test would miss.
- **coupon-collector** — Measures how many draws it takes to see every possible outcome at least once. A generator that quietly favours or starves some values takes a tell-tale number of draws.
- **runs** — Counts ascending/descending streaks. Truly random data has a predictable distribution of streak lengths; too many or too few reveals dependence between draws.
- **interplay-correlation** — Checks that the several values drawn *within one round* are independent of each other — no hidden relationship between, say, reel one and reel three.
- **serial-correlation** — Checks that each outcome is independent of the ones before it — the past must not predict the future.
- **duplicates** — Counts repeated values appearing closer together (or further apart) than chance allows — a classic signature of a weak generator.

</details>
